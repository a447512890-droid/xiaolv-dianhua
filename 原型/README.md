# 待办电话需求原型

静态交互原型。启动与目录说明见[项目首页](../README.md)。

## 启动

在仓库根目录执行 `python3 scripts/preview.py`，访问 <http://127.0.0.1:8765/>。页面实际位于 `/原型/`，从同一仓库的 docs 和 assets 读取资料。无需第三方依赖，不能通过 file:// 读取文档。

## 页面

| 分组 | 页面 |
|---|---|
| 沟通 | 拨号、通话中看板、通话总结、待办详情 |
| 通讯录 | 通讯录、最近沟通记录、拨打前回顾 |
| 待办 | 待办（页内切换空状态／有待办） |
| 记录 | 沟通历史 |
| 文档 | 联系人字段需求、需求列表、更新日志、元数据、商店图 |

模块说明默认关闭；点击波纹圆点展开，可通过右上角关闭按钮、顶部圆点或 Esc 收起，展开与收起均有动画，遵循系统减少动态效果设置。通话总结直接展示自动创建的待办；未完成可编辑、标记完成，完成后仅可删除。拨号固定 +86，号码须为以 1 开头的 11 位数字；无效时呼叫按钮置灰，不显示校验提示。

## 数据读取

- 模块说明：[需求说明.md](../docs/产品需求/需求说明.md)，运行 `python3 scripts/build_requirements.py` 生成 `requirements-data.js`。
- 需求列表：[需求列表.md](../docs/产品需求/需求列表.md)，直接读取表格：序号、模块标识、需求名称、需求描述。
- 联系人字段：[客户字段需求.md](../docs/产品需求/客户字段需求.md)，直接读取正文与表格；保留 `#structure` 路由。
- 更新日志：[更新日志.md](../docs/更新日志.md)，直接读取表格：日期、属性、描述、修改人；仅一条记录。
- 元数据：分别直接读取[元数据.md](../docs/商店资料/元数据.md)和[元数据2.md](../docs/商店资料/元数据2.md)，标签名为元数据1／元数据2。
- 商店图：读取 `../assets/商店图/manifest.json`，分类为待办版／沟通流程版。图片新增、移动或删除后运行 `python3 scripts/build_store_manifest.py` 重新生成清单，再点击“刷新图片”。

Markdown 读取禁用缓存，修改源文档后点击“刷新内容”。图片清单由目录自动扫描生成，不依赖服务器目录列表或符号链接。生成文件应与源文件一起提交。

## 边界

原型采用虚构联系人和通话数据；普通拨号通过 tel 链接调用设备系统电话；待办拨号尚未接入真实通话服务。未接入录音、模型、账号、存储或系统提醒事项。商店图为视觉参考，非正式 App 实际截图。

## 联系人资料维护

通讯录和拨打前回顾提供资料编辑入口，支持组织／公司、职务、关注事项、备注；取消联系目的字段。一个联系人最多 10 个电话号码，支持添加、修改、删除，号码遵循 +86、以 1 开头的 11 位数字规则，禁止同一联系人内重复号码；回顾页可选择号码呼叫。当前静态原型保存于浏览会话内，刷新恢复初始资料。

## 联系人创建来源（已确认）

支持手动新建联系人，也可将拨号记录中的联系人添加至通讯录成为联系人；不支持系统通讯录导入。新增入口和拨号记录添加流程尚待实现。

## 我的与会员

底部新增我的标签，展示用户昵称、ID、会员状态和周／月／年订阅入口；原型手机屏幕外切换会员／非会员预览状态。会员可呼叫并生成新的总结和待办；非会员仅可查看过去的总结和待办，历史任务不提供编辑、完成或删除。通讯录维护权限待确认。价格、支付渠道、续费规则与会员有效期核验待确认，当前原型未接入支付。

“我的”页内非会员／会员标签用于分别评审状态，不是正式产品的会员切换入口。昵称与 ID 为占位数据；实际会员须由订阅服务核验。

## 呼叫模式

呼叫按钮下方选择待办拨号（默认）或普通拨号。两者沿用会员呼叫权限及手机号校验。普通拨号调用系统电话，不进入 App 看板或自动生成总结、待办；待办拨号进入 App 内通话流程。模式选择仅在当前浏览会话保留。

## 通用总结（当前方案）

总结正文为沟通摘要（1 段，优先 100 字以内）、关键要点（最多 5 条，无则隐藏）、约定与待办。我的明确行动自动成为待办，对方承诺保留为约定，双方行动只提取可明确拆出的我的部分。移除销售分析和情绪评分。完整转录与录音播放独立展示；服务器录音服务尚未接入，播放按钮暂不可用。字段文档保留原文件名以兼容现有链接。

左侧原型导航可直接打开“通话中看板”评审页面；实际从拨号按钮发起呼叫仍按会员权限判断。
