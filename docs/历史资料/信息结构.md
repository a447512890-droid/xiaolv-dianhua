# 待办电话信息结构

> 历史资料：本文件保留早期项目导航梳理，不作为当前客户字段需求的数据源。当前以 `docs/产品需求/客户字段需求.md` 和原型实际导航为准。文中 `#` 路由用于原型页面。

以当前原型、需求列表、模块说明和项目文件为依据，按产品标签页与项目文档组织信息。

## 产品导航

- **待办电话**
  - **沟通**
    - [拨号](#dial)
      - 号码输入与删除、标准拨号键盘、呼叫
      - 对应模块：`dialKeypad`
    - [通话中看板](#live)
      - 通话对象、公司、右侧计时、静音、扬声器、挂断圆形图标按钮
      - 客户资料、上次沟通摘要、约定与待办
      - 未关联客户时展示无历史资料状态
      - 对应模块：`callStatusControls`、`callInProgressBoard`
    - [通话总结](#review)
      - 沟通重点：摘要、重点主题、明确约定
      - 通话转录：说话人、原文、时间位置
      - 状态与线索：情绪表现回顾、跟进状态建议
      - 对应模块：`callCommunicationHighlights`、`callTranscript`、`callEmotionReview`、`callFollowUpStatus`、`callActionItemExtraction`
    - [待办详情](#action)
      - 原文依据、事项、负责人、截止日期、关联客户
      - 明确约定自动创建待办，支持编辑事项与截止时间、标记完成
      - iOS 提醒事项同步为可选方案
      - 对应模块：`callActionItemExtraction`、`actionItemConfirmation`、`iosRemindersExport`
  - **通讯录**
    - [通讯录页面](#customers)
      - 通讯录标签：按姓名、公司、电话搜索联系人
      - 最近沟通记录标签：按时间倒序展示沟通，支持关键词搜索和打开回顾
      - 对应模块：`contactDirectory`、`customerCommunicationHistory`、`callSearch`
    - [拨打前回顾](#prep)
      - 客户摘要、最近沟通、未完成约定
      - 对应模块：`callPrepCustomerContext`
  - **待办**
    - [有待办](#todos)
      - 仅展示已确认任务；标记完成或恢复待完成
      - 回看关联客户、通话及约定依据
      - 对应模块：`actionItemConfirmation`
  - **记录**
    - [沟通历史](#history)
      - 搜索客户与沟通关键词
      - 按时间回看沟通记录、通话总结与历史背景
      - 对应模块：`customerCommunicationHistory`、`callSearch`

## 主要信息对象

- **联系人**
  - 基础信息：姓名、公司、号码、角色
  - 关联多次沟通记录与多个待办
- **沟通记录**
  - 沟通对象、时间、内容来源、授权信息
  - 转录：说话人、文字、时间位置
  - 整理结果：摘要、重点、情绪线索、跟进状态与决策建议
  - 关联明确约定和自动创建的待办
- **自动创建的待办**
  - 事项、负责人、截止时间
  - 关联客户、来源通话、原文及时间位置
  - 明确约定自动创建为待办，无需确认创建；创建后可编辑
- **待办**
  - 已确认的任务内容与完成状态
  - 保留来源沟通和客户关联，支持溯源
- **分析依据**
  - 客户明确表达与对话原文
  - 区分原文事实、模型建议和人工确认结果
  - 证据不足时保留未判断或待确认状态

## 主要使用路径

- **直接拨号**：沟通 → 拨号 → 通话中看板 → 挂断 → 通话总结（直接展示客户待办） → 待办详情 → 待办。
- **联系已有客户**：通讯录 → 联系人 → 拨打前回顾 → 通话中看板 → 通话后整理。
- **回看沟通**：通讯录中的最近沟通记录，或记录中的沟通历史 → 对应回顾页面。
- **待办闭环**：通话中明确约定 → 自动创建待办 → 编辑或完成任务 → 完成或继续跟进 → 下次联系时回顾。

## 范围与待确认事项

- **待确认能力**：实际呼叫、通话采集、转录及模型服务、账号与存储、联系人导入、系统提醒同步、支持地区。
- **可选方案**：iOS 提醒事项同步；默认任务主记录仍是 App 内待办。
- **后续探索**：伴侣、家庭、医患、师生、顾问、招聘、团队协作、房产与服务跟进等关系场景，对应 `communicationRelationshipScenes`，尚无独立页面。
- **维护约定**：本文档描述当前信息结构；修改本文档可更新信息结构展示，产品页面和交互逻辑需在原型代码中同步维护。

## 待办标签页状态

- [有待办](#todos)：展示自动创建的任务、截止时间与完成状态，支持编辑并回看原文。
- [空状态](#todos-empty)：展示“暂无待办”、自动创建说明与拨号入口。

## 待办操作规则

- 未完成的待办可编辑、标记完成。
- 已完成的待办仅可删除，不可编辑或恢复待完成。删除后从客户看板、通话总结和待办列表同步移除；原始通话记录仍可回看。
- 通话中看板按“客户资料”“上次沟通”“约定与待办”“未关联客户”分别提供对应的模块说明。
